# demo1kratos

A Kratos service with HTTP and gRPC transports, protobuf-first APIs, Wire dependency injection, OpenAPI generation, and a student CRUD backed by GORM and PostgreSQL. It follows the official [kratos-layout](https://github.com/go-kratos/kratos-layout) template.

## Features

- Kratos HTTP and gRPC server setup.
- Protobuf API definitions and generated Go code, with error codes generated by `protoc-gen-go-errors`.
- Required fields marked with `google.api.field_behavior` and checked by the `validate` middleware on both transports; the service methods keep their own parameter checks too.
- Config values overridable through environment variables with the `KRATOS_` prefix.
- OpenAPI generation.
- Wire-based dependency injection.
- Layered `service`, `biz`, and `data` packages.

## Project Layout

```text
api/                  Protobuf APIs and generated bindings
cmd/demo1kratos/      Application entrypoint
configs/              Local configuration
internal/server/      HTTP and gRPC server construction
internal/service/     Transport-facing service methods
internal/biz/         Usecases and GORM models
internal/data/        Database connection
proto3ps/             Protobuf dependencies (error code annotations)
openapi.yaml          Generated OpenAPI document
```

## Development Commands

Install generators:

```bash
make init
```

Regenerate API bindings and OpenAPI:

```bash
make api
```

Regenerate config protobufs:

```bash
make config
```

Run all generation steps, Wire, and module cleanup:

```bash
make all
```

Build:

```bash
make build
```

Test:

```bash
go test ./...
```

## Run Locally

```bash
go run ./cmd/demo1kratos -conf ./configs
```

Default local ports are configured in `configs/config.yaml`:

- HTTP: `0.0.0.0:8001`
- gRPC: `0.0.0.0:9001`

The database source can be overridden without editing `configs/config.yaml`:

```bash
KRATOS_DATABASE_SOURCE='host=db port=5432 user=postgres password=*** dbname=kratos_examples_db sslmode=disable' go run ./cmd/demo1kratos -conf ./configs
```

## Docker

```bash
docker build -t <your-image-name> .
docker run --rm -p 8001:8001 -p 9001:9001 \
  -v </path/to/your/configs>:/data/conf \

```
